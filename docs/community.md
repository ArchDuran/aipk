# Польза для сообщества

## Проблема которую решает .aipk

Сейчас `.gguf` модели можно скачать одним файлом и сразу запустить.  
Но "умный агент" — это всегда репозиторий с инструкцией:

> *"Установи ChromaDB, настрой LlamaIndex, положи документы сюда,  
> создай конфиг вот так, запусти три сервиса..."*

`.aipk` делает для агентов то, что GGUF сделал для моделей.

## Что меняется

| Сейчас | С .aipk |
|--------|---------|
| Поделиться агентом = поделиться репо + README + часовая настройка | Один файл, запустил и работает |
| RAG требует отдельный сервер (Chroma, Qdrant, Weaviate) | Всё встроено, без серверов |
| Знания, навыки, промпты хранятся в разных местах | Один артефакт |
| Нет стандарта для обмена "агентными знаниями" | Появляется переносимый формат |
| Зависимость от облака (OpenAI Assistants, облачный RAG) | Полностью локально, приватно |

## Ниша не занята

Существуют форматы для:
- Весов модели → `.gguf`
- Адаптеров → `.gguf` (LoRA внутри)
- Конфигурации → Ollama Modelfile

Нет стандарта для **"портативного пакета знаний + поведения агента"**.

## Аналогия с GGUF

До GGUF чтобы поделиться квантизированной моделью нужно было шарить:
- веса по частям
- конфиг токенизатора отдельно
- инструкцию по сборке

GGUF объединил всё в один файл → появился HuggingFace как хаб.

`.aipk` создаёт такую же возможность для агентных знаний.

## Сценарии использования

**Разработчик:** собрал идеальный RAG для кодовой базы своего проекта → упаковал → коллеги запустили без настройки.

**Исследователь:** собрал пакет знаний по медицинским статьям → поделился с командой → каждый запускает локально, данные не уходят в облако.

**Энтузиаст:** скачал `rust-expert.aipk` с хаба → запустил с любым `.gguf` → получил специализированного ассистента за 30 секунд.

**Компания:** создала внутренние пакеты с корпоративными знаниями → сотрудники используют на своих машинах → данные не покидают периметр.
