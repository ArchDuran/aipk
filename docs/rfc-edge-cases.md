# RFC: Edge Cases и обработка ошибок

## Валидация при открытии файла

### Magic bytes

```
Ожидается: 41 49 50 4B ("AIPK")
Если не совпадает → AIPKInvalidMagicError
```

### Версия

```
Текущая: 1
Если version > MAX_KNOWN_VERSION → предупреждение, попытка читать как v1
Если version == 0 → AIPKInvalidVersionError
```

---

## Секции

### Неизвестный тип секции

Тег не входит в: META, PERS, KNOW, SKIL, TOOL, INDX.

**Поведение:** пропустить секцию, логировать предупреждение.  
Это позволяет читать файлы новых версий старыми парсерами (forward compatibility).

### Дублирующиеся секции

Один тип встречается несколько раз.

**Поведение:** использовать первую, остальные игнорировать + предупреждение.  
Исключение: INDX — использовать последнюю (она может быть более полной).

### Отсутствующая META секция

META — единственная обязательная секция.

**Поведение:** `AIPKMissingMetaError`.

### Размер секции не совпадает с реальным

`section.size` указывает за конец файла или выходит за пределы.

**Поведение:** `AIPKCorruptedSectionError(section_type, expected, actual)`.

### Пустая секция (size == 0)

**Поведение:** секция считается отсутствующей, не ошибка.

---

## KNOW секция

### Количество чанков не совпадает с количеством векторов

```
chunks_count != vectors_count
```

**Поведение:** `AIPKKnowledgeCorruptedError` с деталями.

### Размерность эмбеддингов не совпадает с META

```
META.embedding_dim != фактическая размерность в KNOW
```

**Поведение:** `AIPKEmbeddingDimMismatchError(expected, actual)`.

### Невалидный JSONL в chunks блоке

**Поведение:** пропустить битую строку, логировать, продолжить.  
Если битых строк > 10% → предупреждение о повреждении файла.

## Совместимость embedding моделей

### Модель в META не совпадает с доступной в рантайме

```python
if pkg.meta.embedding_model not in runtime.available_models:
    # Вариант 1: пересчитать эмбеддинги с доступной моделью
    # Вариант 2: использовать только keyword search (BM25) без векторов
    # Вариант 3: отказать с AIPKEmbeddingModelMissingError
```

Рантайм должен спросить пользователя что делать.

---

## INDEX секция

### INDEX отсутствует

**Поведение:** читать файл последовательно для построения индекса на лету.  
Медленнее, но работает.

### INDEX указывает на неверные offsets

**Поведение:** игнорировать INDEX, читать последовательно + предупреждение.

---

## Флаги

### Файл помечен как ENCRYPTED, ключ не предоставлен

**Поведение:** `AIPKEncryptionKeyRequiredError`.

### Файл помечен как SIGNED, подпись не валидна

**Поведение:** предупреждение (не ошибка) — пользователь решает доверять ли.

## Таблица кодов ошибок

| Код | Класс | Описание |
|-----|-------|----------|
| E001 | `AIPKInvalidMagicError` | Неверные magic bytes |
| E002 | `AIPKInvalidVersionError` | Версия == 0 |
| E003 | `AIPKMissingMetaError` | Нет META секции |
| E004 | `AIPKCorruptedSectionError` | Размер секции некорректен |
| E005 | `AIPKKnowledgeCorruptedError` | chunks/vectors не совпадают |
| E006 | `AIPKEmbeddingDimMismatchError` | Размерность эмбеддингов не совпадает |
| E007 | `AIPKEmbeddingModelMissingError` | Embedding модель недоступна |
| E008 | `AIPKEncryptionKeyRequiredError` | Файл зашифрован, нет ключа |
| W001 | warning | Неизвестный тип секции (пропущен) |
| W002 | warning | Дублирующаяся секция (первая использована) |
| W003 | warning | Подпись файла не валидна |
| W004 | warning | INDEX некорректен (читается последовательно) |
